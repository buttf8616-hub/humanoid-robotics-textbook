# Implementation Plan: AI Agent with Retrieval-Augmented Answering

**Branch**: `003-ai-agent-rag` | **Date**: 2026-01-22 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/003-ai-agent-rag/spec.md`

## Summary

Build an AI agent using OpenAI Agents SDK that orchestrates retrieval-augmented question answering over the Physical AI & Humanoid Robotics textbook. The agent will:

1. Receive user questions via FastAPI endpoint
2. Call the retrieval tool (Spec 002 `/search` endpoint) to fetch relevant book chunks
3. Use GPT-4 to generate grounded answers strictly based on retrieved content
4. Return formatted responses with source citations
5. Support both full-book context and user-selected text filtering
6. Maintain conversation history for multi-turn dialogues

**Core Technical Approach**: Implement agent as a service layer that wraps OpenAI Agents SDK, defining retrieval as a tool function that the agent MUST call before answering. System prompt enforces zero-hallucination policy: refuse to answer if no relevant content retrieved.

## Phase 1: Design & Contracts

**Goal**: Define data models, API contracts, tool interfaces, and system prompts.

### 1.1 Data Model Design

Document in `data-model.md`:

**AgentRequest** (input to agent service):
```python
class AgentRequest:
    question: str                          # User's question
    conversation_history: list[Message]    # Previous Q&A pairs (optional)
    selected_context: SelectedContext      # URL/section filters (optional)
    top_k: int = 5                         # Number of chunks to retrieve
```

**Message** (conversation turn):
```python
class Message:
    role: Literal["user", "assistant"]
    content: str
    sources: list[SourceCitation]          # Only for assistant messages
    timestamp: datetime
```

**SelectedContext** (user-highlighted text):
```python
class SelectedContext:
    url: str                               # Exact URL to filter
    section: str                           # Section name to filter (optional)
```

**AgentResponse** (output from agent service):
```python
class AgentResponse:
    answer: str                            # Agent's generated answer
    sources: list[SourceCitation]          # Citations for this answer
    retrieved_chunks: list[RetrievalResult] # Raw chunks from retrieval tool
    confidence: Literal["high", "medium", "low", "refused"]
    latency_ms: float
    tokens_used: dict                      # {prompt: int, completion: int, total: int}
```

**SourceCitation** (formatted citation):
```python
class SourceCitation:
    url: str
    title: str
    section: str
    chunk_index: int
    score: float
    excerpt: str                           # First 100 chars of chunk content
```

### 1.3 Tool Interface Contract

Document in `contracts/agent-tool.md`:

**Tool Name**: `retrieve_book_content`

**Tool Description** (for agent):
```
Retrieves relevant content from the Physical AI & Humanoid Robotics textbook
based on a search query. Returns book chunks with source metadata.

IMPORTANT: You MUST call this tool before answering any user question.
Never provide answers without retrieved content.
```

**Tool Function Signature**:
```python
async def retrieve_book_content(
    query: str,
    top_k: int = 5,
    url_filter: Optional[str] = None,
    section_filter: Optional[str] = None
) -> dict:
    """
    Args:
        query: User's question or search query
        top_k: Number of results to return (1-50)
        url_filter: Exact URL to filter results
        section_filter: Section name substring to filter results

    Returns:
        {
            "results": [
                {
                    "content": "...",
                    "url": "...",
                    "title": "...",
                    "section": "...",
                    "chunk_index": 0,
                    "score": 0.89
                }
            ],
            "total_count": 5,
            "latency_ms": 150.5
        }
    """
```

**Tool Implementation**: Calls internal `POST /api/v1/search` endpoint using httpx.

## Risk Analysis & Mitigation

### Risk 1: OpenAI API Rate Limits

**Impact**: High - Could block all agent requests
**Likelihood**: Medium (during peak usage or testing)
**Mitigation**:
- Implement exponential backoff with retries
- Monitor token usage and rate limit headers
- Add request queuing if needed
- Consider caching for common questions (future enhancement)

### Risk 2: Hallucination Despite System Prompt

**Impact**: Critical - Violates core requirement (FR-002)
**Likelihood**: Low-Medium (GPT-4 generally follows instructions well)
**Mitigation**:
- Strong system prompt with CRITICAL INSTRUCTIONS emphasis
- Post-processing validation: check that citations exist in retrieved chunks
- Automated grounding tests: verify response content matches retrieved chunks
- Human evaluation during validation phase

### Risk 3: High Latency (>5 seconds P95)

**Impact**: Medium - Poor user experience
**Likelihood**: Medium (GPT-4 can be slow, plus retrieval overhead)
**Mitigation**:
- Stream responses if OpenAI supports it (progressive rendering)
- Optimize retrieval (already <500ms per Spec 002)
- Set reasonable OpenAI timeout (3-4 seconds)
- Monitor latency metrics and alert on degradation

### Risk 4: Token Budget Exhaustion (Long Conversations)

**Impact**: Medium - Conversations truncated or fail
**Likelihood**: Medium (especially with large retrieved chunks)
**Mitigation**:
- Implement sliding window for conversation history (e.g., last 10 turns)
- Summarize old conversation context (future enhancement)
- Truncate retrieved chunks if needed (prioritize by score)
- Monitor token usage per request

### Risk 5: Retrieval Service Downtime

**Impact**: High - Agent cannot function without retrieval
**Likelihood**: Low (but possible during deployments)
**Mitigation**:
- Implement circuit breaker pattern
- Return 503 with retry-after header
- Add health check endpoint for agent service
- Graceful degradation message to user
